# Деплой на ACLClouds

Бот работает на Bun. Локальные `start.cmd` и `watchdog.ts` нужны только на Windows
и на хостинге не используются — ACLClouds сам перезапускает процесс.

## Первый запуск

1. Загрузи проект на ACLClouds (Git-импорт или загрузка файлов).
2. Runtime: **Bun**.
3. Поля панели:

| Поле | Значение |
| --- | --- |
| Git Repository Address | URL репозитория с кодом |
| Git Branch | `main` |
| Auto Update | `1` — подтягивать последние файлы при запуске |
| Skip all install stuff | `0` — зависимости ставятся из `package.json` / `bun.lock` |
| Main file | `bot.ts` |
| Additional Bun Packages | пусто |
| Git Username / Access Token | только для приватного репозитория, токен с доступом на чтение |
| Environment Variables | `DISCORD_BOT_TOKEN=<токен>` |

4. Не добавляй `.env` с токеном в публичный репозиторий: бот сначала читает
   `DISCORD_BOT_TOKEN` из окружения и только потом смотрит в `.env`.
5. `data.json`, `battles.json`, `errors.log`, `backups/`, `.env`, `node_modules/`
   и `dist/` уже в `.gitignore` и не должны попадать в Git.
6. Auto Update срабатывает **при запуске/рестарте**, а не по push. После пуша
   нажми Restart в панели. Если менялись зависимости, `Skip install = 0`
   запустит установку заново.

## Файлы, которые должны сохраняться

Эти файлы/папки создаются в рабочей директории и должны переживать рестарт:

- `data.json` — пользователи, монеты, квесты, скины.
- `battles.json` — активные бои, дуэли и забеги.
- `errors.log` — ошибки.
- `backups/` — ежедневные копии `data.json` и `battles.json` (хранятся 7 дней).

При обновлении бота **не затирай** эти файлы. Если заливаешь проект целиком,
сначала скачай их из панели и верни обратно после обновления.

## Как обновлять

В официальной документации ACLClouds описан только разовый Git-импорт, без
CI/CD. Если в твоей панели есть отдельный переключатель **Auto Update / Git
Auto-Update**, включи его и укажи ветку: тогда панель сможет подтягивать
изменения из репозитория. Поведение (при рестарте или по расписанию) лучше
проверить в самой панели — в документации оно не описано.

Для автообновления репозиторий должен содержать только код. В проекте уже есть
`.gitignore`: `data.json`, `battles.json`, `errors.log`, `backups/`, `.env`,
`node_modules/` и `dist/` не попадут в Git и не будут затираться при pull.

Варианты обновления:

1. **Загрузка файлов:** замени изменённые `.ts`/`.json`/`.md` файлы и нажми
   Restart.
2. **Повторный Git-импорт:** импортируй репозиторий заново, затем верни
   `data.json`, `battles.json`, `errors.log` и `backups/` из резервной копии.
3. **Консоль хостинга:** если доступен `git`, можно сделать `git pull` вручную,
   но это всё равно не автомат — после pull нужен Restart.

Я не имею прямого доступа к твоей панели ACLClouds, поэтому не могу сам нажимать
Restart или загружать файлы. Я готовлю изменения и даю список файлов/команд —
их нужно применить в панели. Прямое обновление возможно только на VPS с SSH
или если ты сам дашь доступ к панели (делиться доступом не рекомендуется).

## Ограничения бесплатного тарифа

- 0.5 vCPU, 315 MB RAM, 715 MB диска.
- Продление вручную каждые 4 дня.
- Тяжёлые AI-прогоны через `/дебаг` лучше не запускать на бесплатном тарифе:
  они грузят CPU и память.
- `sharp` нужен только инструментам загрузки эмодзи, не самому боту.

## Проверка после деплоя

- В логах: `[bot] вошёл как ...; команд: 7`.
- `/команды` открывается, `/пве` показывает босса, тренировку и выживание.
- `data.json` не пустой, если переносишь существующую базу.
